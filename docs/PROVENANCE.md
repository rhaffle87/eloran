# Provenance and Citation Verification Audit (PROVENANCE.md)

This document records the provenance, retrievable URLs (publisher DOI, official institutional repository, or government standards portal), exact retrieved evidence strings, publication dates, and verification status for all citations, empirical models, and station data used in **SIMULORAN**.

Per project protocol:
- Every citation must record: **URL | Evidence String | Date / Details | Status**.
- Status is classified as either **SOURCED** or **UNVERIFIED**.
- "SOURCED" requires: an active URL actually fetched and machine-verified, plus an exact evidence string (title and author line) confirmed in the fetched response.
- If a page cannot be fetched, does not show the title/authors, or blocks automated access (e.g. WAF/403/503), the row is marked **UNVERIFIED**.
- Never construct URLs or identifiers (DOIs, repository UUIDs, ION article IDs) from patterns.
- Do not fill in details from memory (defense dates, ISBNs, page ranges, venues) if not present on the fetched page.
- Machine verification is executed via `npm run check:provenance` (`scripts/check-provenance.mjs`).

## 3. Groundwave Engine Reference Output Validation (ITU-R P.368 / GRWAVE)

- **Source Implementation & Binary Origin**: Field strength attenuation reference curves were generated using the CCIR/ITU-R P.368-9 Fortran binary (`grwave.bin.exe`), pre-compiled (dated June 2, 2026) within the local `space-physics/grwave` submodule. Invoked via Python `SubprocessEngine` with standard parameters (100 kHz, 1 kW radiated power, flat-earth / residue-series transitions).
- **Validation Dataset**: Ground-truth fixtures are archived in [`src/lib/__tests__/fixtures/grwave-reference.json`](file:///E:/Projects/simuloran/src/lib/__tests__/fixtures/grwave-reference.json):
  - **Field Strength**: $dB\mu V/m$ values directly parsed from `grwave.bin.exe` standard output across four canonical ground media (seawater $5.0\,\text{S/m}$, marsh $0.02\,\text{S/m}$, agricultural land $0.005\,\text{S/m}$, mountain $0.001\,\text{S/m}$) over $10\text{ to }1000\,\text{km}$.
  - **Phase Lag & Timing Delay**: The Fortran GRWAVE CCIR binary computes field amplitude only (does not output phase). Phase lag ($\Delta\phi$), numerical distance ($p$), and phase delay ($\mu\text{s}$) in the reference dataset were computed in Python using the standard analytical Sommerfeld-Norton surface impedance formulation ($p = (\pi d / \lambda) |\eta|^2$, $\Delta\phi \approx \arctan(\sqrt{p}\cos(b/2)) + \frac{p}{2+p}\sin(b/2)$).
- **Methodological Disclosure & Circularity Guard**:
  - The JavaScript engine in [`src/lib/grwave.js`](file:///E:/Projects/simuloran/src/lib/grwave.js) implements the identical analytical Sommerfeld surface impedance equations and multi-segment Millington reciprocal path averaging method (ITU-R P.368-10 Annex 1, §3).
  - The $< 0.0001\,\mu\text{s}$ tolerance in unit tests is an exact cross-language floating-point verification confirming that the JavaScript implementation precisely reproduces the Python reference implementation of the Sommerfeld-Norton equations. It is **not** an independent validation against Fortran phase output.
- **Atmospheric Noise Caveat**: While ITU-R P.368 groundwave propagation is rigorous for LF terrestrial signals, the atmospheric noise figures in ITU-R P.372 are documented in navigation literature (e.g. Boyce et al., 2005, *Atmospheric Noise Mitigation for Loran*) as having been developed for communications receiver bandwidths rather than navigation pulse timing error budgets, and are treated with appropriate caveats in SIMULORAN.
